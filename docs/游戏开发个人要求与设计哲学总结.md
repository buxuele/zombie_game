# 游戏开发个人要求与设计哲学总结

基于本项目全流程的迭代反馈与打磨过程，全面提炼并总结出关于游戏开发的核心要求与设计哲学。

## 1. 细节决定成色与拒绝粗制滥造

1. 细节决定质感：游戏不仅仅是实现基础规则，更在于每一帧的动作姿态、微表情、粒子反弹、形变压缩与音效协同。
2. 拒绝粗糙占位：所有道具、载具与角色必须使用高精细度资产，彻底告别粗糙敷衍的占位图。
3. 彻底删除生硬机械感：任何状态切换（如感染蜕变、载具掀翻、形态解除）必须具备完整的微过渡过程，绝不接受凭空消失或瞬间瞬移。

## 2. 物理动量、视觉重量感与直觉逻辑

1. 符合现实直觉的行为逻辑：当军团力量不足以掀翻大型载具时，绝不接受瞬间暴毙，必须先在车头前拼死推挤推搡、车身剧烈震颤颠簸，随后才被缓缓推倒碾压并伴随慢动作特写。
2. 群体蓄力与爆发冲击力：当人数达标掀翻公交车或飞机时，领头僵尸顶住车头，后排全员在 0.45 秒内向前急速叠罗汉堆叠挤压并发出金属受力重音，随后爆发群体齐声怒吼同步掀翻升空，体现真实的群体力量感。
3. 连环连锁的正向反馈：掀翻载具必须伴随车门震飞、内部乘客惊慌四散逃跑，军团顺势一拥而上将其全部扑倒感染，形成掀车即大暴兵的爽快连锁。

## 3. 操作手感、技巧成就感与合理难度曲率

1. 平台跳跃的技巧成就感：拒绝无脑的全屏自动磁铁吸附，道具与宝箱必须悬浮在空中，玩家必须通过精准判断起跳时机，用头部或身体撞中宝箱方可解锁奖励。
2. 人体工学高度校准：空中奖品高度必须经过精确数学测算，确保玩家单次轻跳即可稳稳触及，杜绝永远够不到的高空盲区。
3. 杜绝必死死局设计：道路断崖等障碍跨度必须保持在舒适安全的微型跨度内，并在缺口前方设立清晰的警示路障与指引金币弧线，杜绝任何无法预判的猝死陷阱。
4. 核心输入绝对零延迟：起跳判定必须毫秒级响应，严格限定仅在竖直速度大于等于 0 的下落阶段才触发着陆检测，绝不允许领头角色起跳被当帧误判阻断。

## 4. 美术风格亲和力、全屏沉浸与无缝场景流转

1. 亲和可爱的萌系美术风格：角色形象必须友好、可爱、富有生机，参考 Zombie Tsunami 的经典大圆眼、露齿大笑、红衫牛仔裤的萌版 Chibi 形象，拒绝吓人或粗糙的写实丑陋建模。
2. 全屏无黑边沉浸视野：游戏视口必须完全占满浏览器 100% 宽度与高度，窗口拉伸时自适应扩展横向视野。
3. 消除中轴垂直硬切拼缝：视差背景平铺必须采用水平镜像对称算法，彻底根除屏幕中轴线处的垂直生硬拼接线。
4. 真实地理过渡段实体建模：场景切换绝不能生硬硬切，必须通过穿山隧道、跨海悬索大桥等真实地理实体进行平滑过渡，配套光影遮蔽、吊灯体积光与路面材质自然演进。

## 5. 视听多巴胺联动与阶梯式反馈

1. 音阶攀升反馈：连续跳跃收集金币时，音效必须按自然大调音阶逐级爬升，吃满整组金币触发清脆和弦。
2. 收集物动态飞入：金币与大脑收集后化作发光光球沿贝塞尔曲线飞入顶部 HUD 胶囊，触碰瞬间触发心跳缩放动画与数字跳动。
3. 结算界面拉霸式清算：游戏结束时数据采用拉霸式逐帧递增音效展示，打破纪录全屏绽放金色礼花。

## 6. 真实工具实机自测与全透明监控

1. 严禁用户当人肉测试员：开发者必须通过 Chrome DevTools MCP 与自动化测试在真实浏览器环境中跑通全流程、验证所有极端边界并截取超清实机画面确认。
2. 实时运行日志透明监控：必须内置全功能日志系统，实时分类记录跳跃冲量、载具堆叠、平民感染与商城交易等底层事件，方便直观排查。

## 7. 一键闭环与极简操作纪律

1. 一键启动直达：提供开箱即用的启动脚本，自动补齐依赖并在默认浏览器中拉起页面。
2. 局内核心按键直觉布局：顶部常驻暂停继续、声音开关与调试日志面板，单次点击即完成最终诉求。
3. 进程安全自检：任务结束前必须主动查杀并关闭所有后台测试服务与端口，严禁残留常驻进程。
